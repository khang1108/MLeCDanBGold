\section{Interactive Hypothesis Inspection and Trajectory Correction}
\label{sec:interactive-hypothesis-correction}

SHI exposes two intermediate representations for direct interaction during
multi-event search. In the \emph{pre-retrieval} stage, the Query Hypothesis
represents the current interpretation of a narrative as an ordered sequence of
events that can be inspected and edited before search. In the
\emph{post-retrieval} stage, EventTrail represents the temporal alignment of an
individual candidate video as an ordered path over event occurrences. As
illustrated in Fig.~\ref{fig:layer3}, edits to the Query Hypothesis determine
the event specifications used by retrieval, whereas EventTrail actions are
translated into temporal constraints and re-decoded over retained retrieval
evidence. The two stages therefore expose semantic decomposition and temporal
alignment as separate but connected interaction points in the retrieval
workflow.

\subsection{Pre-retrieval Query Hypothesis}
\label{sec:query-hypothesis}

The Query Hypothesis represents the current semantic interpretation of a
multi-event request before retrieval is executed. Given a narrative query, the
LLM proposes an ordered sequence of events $(E_1,\dots,E_N)$. For the initial
decomposition, each proposed event must correspond to a verbatim fragment of
the original query; the server verifies these fragments against the source text
and falls back to a single-event representation if the decomposition cannot be
grounded. The resulting event sequence is shown explicitly to the operator
together with its temporal order and any event-specific reference images.
Rather than treating the decomposition as a fixed parser output, SHI keeps it
as the active search hypothesis from which the downstream retrieval plan is
constructed.

The editor supports event-level structural operations including splitting and
merging events, changing their order, editing or adding event descriptions, and
attaching or removing reference images. Each proposed operation can first be
previewed without modifying the active hypothesis, allowing the operator to
compare the current and proposed event sequences before committing the change.
A committed operation creates a new monotonically revisioned hypothesis and
stores the previous state in a bounded session history, from which the latest
change can be undone. Subsequent retrieval uses the committed revision, so
structural edits directly change the event specifications supplied to the
multimodal scoring and temporal-alignment pipeline.

\subsection{Post-retrieval EventTrail}
\label{sec:event-trail}

EventTrail operates on the decoded temporal path of an individual candidate
video after the initial retrieval. For a query with $N$ events, the trail
contains one selected frame occurrence for each event in temporal order,
together with the corresponding retained event--frame evidence. An operator can
focus on any event whose current occurrence appears inconsistent with the
video content. EventTrail then identifies temporally distinct alternative
occurrences for that event and decodes a complete path for each alternative.
The interface therefore presents the effect of an alternative on the entire
event sequence rather than showing the alternative frame in isolation. These
previews do not modify the active trail until the operator explicitly commits
an action.

Three actions are provided for occurrence-level correction. \emph{Keep}
anchors the occurrence currently assigned to an event, \emph{Use} anchors the
representative occurrence of a selected alternative path, and \emph{Reject}
excludes the temporal interval associated with a selected occurrence mode.
These actions update the session's temporal constraints while leaving the
underlying Evidence Snapshot unchanged. The dynamic-programming decoder then
re-computes the highest-scoring feasible path for the selected video under the
updated anchors and exclusion intervals. Because the event--frame evidence is
retained in the snapshot, this correction step does not repeat query embedding
or corpus-level retrieval. EventTrail also maintains a bounded history of
constraint states, allowing the most recent action to be undone before further
inspection or submission.
