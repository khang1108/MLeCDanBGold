\section{System Overview}
\label{sec:system}
SHI separates offline corpus preparation from the online retrieval workflow.
During offline preparation, keyframes are enriched with contextual descriptions
generated by a vision-language model (Qwen3-VL-8B-Instruct~\cite{qwen2025qwen3vl}) to
form FrameContext metadata. Together with visual embeddings and spoken
transcripts, these are compiled into dense FAISS indexes~\cite{johnson2019billion}
alongside a lexical BM25 index.
At runtime, as illustrated in Fig.~\ref{fig:layer2}, these read-only artifacts
are queried for each event in the active Query Hypothesis, so online processing
is limited to query encoding, retrieval, score fusion, and temporal alignment.

\subsection{Multi-event KIS Retrieval Pipeline}
\label{sec:kis-retrieval}

Multi-event KIS is formulated as multimodal event scoring followed by joint
temporal alignment. Given an ordered sequence of events from the Query
Hypothesis, each textual event is evaluated against several retrieval sources:
SigLIP2~\cite{tschannen2025siglip2} provides visual text--frame similarity,
BGE-M3~\cite{chen2024bgem3} provides dense FrameContext and ASR evidence, and
BM25~\cite{robertson2009bm25} provides lexical matching over frame-associated
text. Optional reference images contribute additional
SigLIP2 image--frame similarity scores. Each component is normalized by robust
quantile calibration, which also yields a per-event reliability. Fusion weights
are routed by lexical cues in the event text, scaled by this reliability, and
renormalized over the sources available for each frame, giving an event--frame
score matrix $S[v,e,f]$ for each video $v$. A dynamic-programming decoder then
selects one frame $f_e$ per event under strict temporal order, maximizing
$\sum_e S[v,e,f_e]-\lambda\sum_{e>1}(t_{f_e}-t_{f_{e-1}})$ with a linear gap
penalty $\lambda=10^{-5}$ per millisecond. Scoring covers the full corpus and
the decoder, linear in the number of frames, runs on every video without a
video-level shortlist; videos are ranked by their decoded path scores.

\subsection{Evidence Snapshots and Competition Integration}
\label{sec:evidence-snapshots}

After the initial KIS execution, SHI captures an in-memory Evidence Snapshot
that retains, for the returned candidates, immutable event--frame evidence,
event identifiers, initial decoded paths, and the decoder configuration.
Constraints from EventTrail actions are kept separately from this frozen
evidence and supplied to the temporal decoder, which re-computes the path for
the selected video without repeating query embedding or corpus index search.
Selected frames are submitted to the Distributed Retrieval Evaluation Server
(DRES)~\cite{rossetto2021dres} directly from the interface.
