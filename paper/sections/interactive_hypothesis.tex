\section{Interactive Hypothesis Inspection and Path Alignment}
\label{sec:interactive-hypothesis-correction}

As illustrated in Fig.~\ref{fig:layer3}, SHI supports interaction at two
stages of multi-event KIS. Before retrieval, the \emph{Query Hypothesis}
exposes the event-level representation derived from the narrative query and
allows the user to revise it before search. After retrieval,
\emph{EventTrail} exposes the temporal alignment of a candidate video and
incorporates occurrence-level feedback as constraints on subsequent path
decoding.

\begin{figure}[!t]
  \centering
  \includegraphics[width=0.60\textwidth]{layer3.pdf}
  \caption{The two hypothesis-level interaction mechanisms in SHI.
  (a) Query Hypothesis exposes the initial LLM-derived event

  committed. (b) EventTrail exposes the decoded temporal path of a
  candidate video and presents temporally distinct alternatives as complete
  ordered paths. Keep, Use, and Reject actions introduce anchor or exclusion
  constraints, after which the path is re-decoded from the retained evidence
  snapshot.}
  \label{fig:layer3}
\end{figure}

\subsection{Pre-retrieval Query Hypothesis}
\label{sec:query-hypothesis}

Given a multi-event narrative, Qwen3~\cite{qwen2025qwen3} produces an ordered
sequence of event descriptions, with each generated event grounded to a span
of the original query. SHI exposes this event-level query representation as a
\emph{Query Hypothesis} before retrieval rather than immediately executing it.
Users can edit event descriptions, split or merge events, change their order,
and associate reference images with individual events. Proposed revisions are
previewed together with the current hypothesis before being committed, and
the most recent revision can be undone. Once accepted, the resulting event
sequence defines the retrieval units used by the multimodal scoring and
temporal-alignment stages.

\subsection{Post-retrieval EventTrail}
\label{sec:event-trail}

EventTrail operates on the temporal path decoded for an individual candidate
video. For a query containing $N$ events, a path assigns one frame occurrence
to each event while preserving the event order. When the user focuses on an
event $E_e$, SHI retrieves alternative occurrences according to their
compatibility with the complete event sequence rather than ranking candidate
frames solely by the local score $S[v,e,f]$.

Let $P_e(f)$ and $Q_e(f)$ denote the best prefix and suffix scores,
respectively, when event $E_e$ is constrained to frame $f$. The score of the
best complete path containing this assignment is

\begin{equation}
C_e(f) = P_e(f) + Q_e(f) - S[v,e,f],
\label{eq:conditioned-path-score}
\end{equation}

where the subtraction avoids counting the local event--frame score twice.
Candidates are ranked by $C_e(f)$ and temporally suppressed to obtain distinct
occurrences. In our implementation, at most $K_{\mathrm{alt}}=4$
alternatives are retained with a minimum temporal separation of
$\Delta_{\mathrm{alt}}=5$ seconds. Each alternative is displayed together
with its complete decoded path, so that changes induced in the remaining
event assignments are visible before the user commits the correction.

Each alternative carries a bounded temporal neighborhood capped at eight seconds.
EventTrail supports three occurrence-level actions: \emph{Keep} anchors the selected
occurrence, \emph{Use} anchors a previewed alternative, and \emph{Reject} introduces
an exclusion constraint over the alternative's temporal neighborhood. After each
action, SHI re-decodes the complete event sequence jointly under the updated
constraints from the Evidence Snapshot, allowing path corrections without re-querying
the corpus. Actions can be undone without altering underlying retrieval evidence.
