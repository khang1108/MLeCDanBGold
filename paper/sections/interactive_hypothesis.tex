\section{Interactive Hypothesis Inspection and Path Alignment}
\label{sec:interactive-hypothesis-correction}

SHI exposes two intermediate representations for direct interaction
(Fig.~\ref{fig:layer3}): Query Hypothesis edits determine the events used by
retrieval, whereas EventTrail actions become temporal decoding constraints.

\subsection{Pre-retrieval Query Hypothesis}
\label{sec:query-hypothesis}

The Query Hypothesis represents the current semantic interpretation of a
multi-event request before retrieval is executed. Given a narrative query, a
% TODO: replace with the exact model checkpoint actually deployed, e.g. Qwen3.8-27B.
large language model (Qwen3~\cite{qwen2025qwen3}) proposes an ordered sequence
of events $(E_1,\dots,E_N)$. For the initial decomposition, each proposed event
must correspond to a verbatim fragment of the original query; the server
verifies these fragments against the source text and falls back to a single-event
representation if the decomposition cannot be grounded. The resulting event
sequence is shown explicitly to the operator together with its temporal order
and any event-specific reference images.

The editor supports event-level structural operations including splitting and
merging events, changing their order, editing or adding event descriptions, and
attaching or removing reference images. Operators can also provide conversational
feedback to prompt Qwen3 for targeted hypothesis revisions. Each proposed
operation can first be previewed without modifying the active hypothesis, allowing the operator to
compare the current and proposed event sequences before committing the change.
Committing an edit creates a new hypothesis revision, which subsequent
retrieval uses; the previous revision can be restored through undo.

\subsection{Post-retrieval EventTrail}
\label{sec:event-trail}

EventTrail operates on the decoded temporal path of an individual candidate
video after the initial retrieval. For a query with $N$ events, the active
trail contains one selected frame occurrence for each event in temporal order.
When an operator focuses on event $E_e$, SHI searches for alternative
occurrences by evaluating candidate frame positions for that event in the
context of the complete event sequence, rather than ranking frames only by
their local event score $S[v,e,f]$.

Let $P_e(f)$ denote the score of the highest-scoring valid prefix path ending
with event $E_e$ at frame $f$, and let $Q_e(f)$ denote the score of the
highest-scoring valid suffix path starting from the same assignment. The score
of the best complete path constrained to pass through frame $f$ at event
$E_e$ is

\begin{equation}
C_e(f) = P_e(f) + Q_e(f) - S[v,e,f].
\label{eq:conditioned-path-score}
\end{equation}

The subtraction removes $S[v,e,f]$, which is counted in both terms, so
$C_e(f)$ evaluates an occurrence by the best complete chronological path that
contains it rather than by its frame score in isolation. Candidate frames are considered
in descending order of $C_e(f)$. To avoid presenting several alternatives from
the same temporal neighborhood, SHI retains a candidate only if its timestamp
is at least $\Delta_{\mathrm{alt}}$ away from every previously retained
representative. The process stops after $K_{\mathrm{alt}}$ alternatives have
been selected. In the current implementation,
$K_{\mathrm{alt}}=4$ and $\Delta_{\mathrm{alt}}=5$ seconds. Each retained
representative is presented together with its complete decoded path, allowing
the operator to inspect how choosing that occurrence affects the remaining
events before committing a change.

Each retained representative at timestamp $t_j$ is assigned a bounded
occurrence interval $I_j$ with radius
$r_j=\min(r_{\max},\tfrac{1}{2}\min_{k\neq j}|t_j-t_k|)$, where $r_{\max}=8$
seconds and $r_j=r_{\max}$ when no other representative exists; intervals are
clipped to the video boundaries, so $I_j$ defines the temporal neighborhood
affected by rejection.

The operator can apply three occurrence-level actions. Keep anchors the
frame currently assigned to the focused event. Use anchors the
representative frame of a selected alternative and re-decodes the complete
path under that anchor. Reject adds the corresponding interval $I_j$
to the exclusion set of the focused event only. Occurrences of the remaining
events are not directly excluded, although their selected frames may change
when the complete path is re-decoded under the updated temporal constraints.
A Keep or Use that admits no chronologically feasible path, such as an anchor
that contradicts the order of an existing one, is refused and leaves the
constraints unchanged. If rejections remove every feasible path, the trail is
marked exhausted and the last valid path is retained; the most recent action
can be undone. Submissions from EventTrail use the frame selected with Use.
EventTrail can only correct alignments within videos in the snapshot; if the
target video was not retrieved, the operator revises the Query Hypothesis
instead.
