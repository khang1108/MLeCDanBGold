# HCMAI Phase B Corpus and Schema Cleanup Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Separate runtime corpus reads from offline artifact construction, replace `DataService` with a read-only `Corpus` facade, and move runtime internal models away from the global Pydantic schema package without changing existing artifacts.

**Architecture:** Runtime search lives under `src/hcmai/` and reads already-published frame/evidence/index artifacts. Artifact-producing code moves under a real `offline/` package while retaining the same commands and output conventions. `Corpus` becomes the only public runtime data facade; specialist stores and asset resolution remain private implementation details.

**Tech Stack:** Python 3, dataclasses, Pydantic v2 only at API/offline validation boundaries, pandas/Parquet, NumPy/FAISS, existing C++/CMake keyframe extractor, pytest.

**Spec:** `docs/superpowers/specs/2026-08-30-hcmai-temporal-search-cleanup-design-v2.md`

## Global Constraints

- Start only after the Phase A plan is green and merged/stable.
- Preserve the current `artifacts/enrichment/**`, `artifacts/frame_store/**`, and `artifacts/indexes/**` layouts exactly.
- Do not rename artifact files, frame IDs, manifests, index bundle members, embedding files, or keyframe image conventions.
- Do not change caption, OCR, ASR/transcript, object, embedding, index-building, or C++ keyframe algorithms.
- `Corpus.open(...)` reads existing artifacts only and fails fast for required missing inputs; it must never run generation.
- Runtime public callers import `Corpus`, not `FrameStore`, evidence stores, transcript stores, or asset resolvers.
- Internal runtime models use frozen/slotted dataclasses; API contracts remain Pydantic.
- Offline code should not depend on runtime `hcmai` domain dataclasses; artifact formats are the integration boundary.
- Keep existing standalone offline CLIs separate; do not create a unified CLI.
- Index loading/search remains runtime Retrieval ownership; index/embedding artifact creation belongs to offline tooling.

**Files:**

**Interfaces:**
- Produces: `Corpus.open(...)` and the only public runtime data facade.

Target public API:

```python
class Corpus:
    @classmethod
    def open(
        cls,
        frames_path: str | Path,
        evidence_paths: Mapping[RetrievalSource, str | Path] | None = None,
        *,
        dataset_root: str | Path | None = None,
        object_counts_path: str | Path | None = None,
        transcript_path: str | Path | None = None,
        video_metadata_path: str | Path | None = None,
    ) -> "Corpus": ...

    def frame(self, frame_id: str) -> Frame: ...
    def frames(self, frame_ids: Sequence[str]) -> list[Frame]: ...
    def caption(self, frame_id: str) -> str | None: ...
    def ocr(self, frame_id: str) -> str | None: ...
    def objects(self, frame_id: str) -> tuple[str, ...]: ...
    def transcript(self, video_id: str, start_ms: int, end_ms: int) -> str | None: ...
    def transcript_segments(self, video_id: str, start_ms: int, end_ms: int) -> tuple[TranscriptSegment, ...]: ...
    def title(self, video_id: str) -> str | None: ...
    def image_path(self, frame_id: str) -> Path: ...
    def thumbnail_path(self, frame_id: str) -> Path: ...
```
